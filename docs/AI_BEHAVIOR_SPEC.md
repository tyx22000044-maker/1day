# 1Day — AI 行为规范

> 版本：v3.0 · 最后更新：2026-06-29
> 目的：约束 AI 功能的行为边界，防止 AI Coding 写出"AI 直接保存数据"等违背产品原则的逻辑。
> 家族级原则见：PRODUCT_PRINCIPLES.md 第四节

---

## 一、AI 可以做

### 生成草稿

- 根据用户自然语言输入，生成结构化的任务/事件/想法草稿
- 从用户输入中提取日期、时间、优先级等结构化字段
- 生成复盘摘要（基于用户主动请求 + 已完成/未完成统计数据）
- 建议笔记分类或整理方案

### 读取上下文（仅用户主动触发时）

- 读取今日事项摘要，注入 AI 对话上下文
- 读取近期事项（未来 7 天），注入 AI 对话上下文
- 读取复盘统计数据（完成数/未完成数），注入 AI 对话上下文

### 交互

- 在聊天界面回答用户关于计划、日程的问题
- 提供快捷建议 Chips（预设常见操作）
- 处理语音输入转文字后的文本

---

## 二、AI 不可以做

### 绝对禁止

- ❌ **直接写入数据库**：所有 AI 输出必须先作为草稿展示，经用户确认后才保存
- ❌ **自动删除或修改用户已有数据**：AI 不能修改已保存的任务/笔记/事件
- ❌ **后台静默调用 AI 模型**：每次 AI 请求必须由用户主动触发（发送消息、点击按钮）
- ❌ **擅自读取全部数据**：AI 上下文只包含当前任务所需的最少数据
- ❌ **读取笔记全文内容**：除非用户主动请求（如"帮我整理这条笔记"），否则不发送笔记正文给 AI
- ❌ **读取证件信息**：证件数据永远不发送给 AI 服务商
- ❌ **提供医疗/法律/金融建议**

### 行为约束

- AI 输出必须标注「AI 生成」或「草稿」
- AI 确认页必须允许用户编辑每一个字段
- AI 确认页必须有「取消」按钮，取消后不写入任何数据
- AI 请求超时必须有明确的错误提示和重试入口
- AI 解析失败时，保留用户原始输入，不丢弃

## 三、AI 上下文规则

### 什么数据可以发送给 AI

| 数据 | 是否发送 | 条件 |
|------|---------|------|
| 用户当前输入的消息 | ✅ 总是 | — |
| 对话历史 | ✅ 总是 | 当前会话的历史消息 |
| 今日事项摘要 | ✅ 可选 | 仅 `get_today_tasks` 意图触发时 |
| 近期事项摘要 | ✅ 可选 | 仅 `get_upcoming` 意图触发时 |
| 完成统计数据 | ✅ 可选 | 仅 `get_review_summary` 意图触发时 |
| 笔记正文 | ❌ 默认不发 | 仅用户明确请求时（如"帮我整理这条笔记"） |
| 证件信息 | ❌ 永不 | — |
| API Key | ❌ 永不 | Key 只用于 HTTP 请求头，不进 prompt |

### 摘要注入格式

当 AI 需要用户数据作为上下文时，只发送摘要，不发送完整数据。

**今日事项摘要**（`get_today_tasks`）：
```
今天有 5 个任务：
- [待办] 交房租（高优先级，截止今天）
- [待办] 下午开会（普通优先级，截止今天）
- [待办] 买菜
- [已完成] 取快递
- [已完成] 回复邮件
```

**近期事项摘要**（`get_upcoming`）：
```
未来 7 天有 8 个任务：
- 明天：交报告、约牙医
- 周三：团队周会
- 周五：提交方案
- 下周一：出差准备
```

## 四、结构化意图 JSON Schema

### V1.0：create_task

**AI 输出格式**：
```json
{
  "intent": "create_task",
  "data": {
    "title": "交房租",
    "notes": "转账到房东招商银行",
    "dueDate": "2026-07-01T00:00:00Z",
    "priority": "high",
    "reminderTime": null
  }
}
```

**字段规则**：
- `title`：必填，String
- `notes`：可选，String，默认 ""
- `dueDate`：可选，ISO 8601 格式，nil 表示不设日期
- `priority`：可选，枚举 "none" / "low" / "medium" / "high"，默认 "none"
- `reminderTime`：可选，ISO 8601 格式

**AI 无法确定的字段**：设为 null，确认页让用户手动填写。

### V1.2：create_event

**AI 输出格式**：
```json
{
  "intent": "create_event",
  "data": {
    "title": "Q3 规划会议",
    "notes": "",
    "startDate": "2026-07-01T10:00:00+08:00",
    "endDate": "2026-07-01T12:00:00+08:00",
    "location": "3 楼会议室",
    "priority": "none",
    "reminderTime": "2026-07-01T09:45:00+08:00"
  }
}
```

### V1.2：create_tasks

**AI 输出格式**（一句话多任务）：
```json
{
  "intent": "create_tasks",
  "data": [
    {
      "title": "买机票",
      "dueDate": "2026-07-10T00:00:00Z",
      "priority": "high"
    },
    {
      "title": "订酒店",
      "dueDate": "2026-07-10T00:00:00Z",
      "priority": "medium"
    },
    {
      "title": "准备行李",
      "dueDate": "2026-07-14T00:00:00Z",
      "priority": "low"
    }
  ]
}
```

**确认流程**：逐条展示，用户可单独编辑或跳过每一条。

### V1.3：create_idea

```json
{
  "intent": "create_idea",
  "data": {
    "title": "学摄影",
    "content": "可以先从手机摄影开始，找个线上课程"
  }

```

## 五、Prompt 构建规则

### 系统 Prompt 结构

```
你是 1Day 的 AI 助手，帮助用户管理任务和日程。

你的能力：
- 根据用户描述创建任务或事件草稿
- 回答关于计划和日程安排的问题
- 帮助用户回顾和复盘

规则：
- 你只生成草稿，用户确认后才会保存
- 如果用户的描述不够清晰，主动询问缺少的信息
- 日期解析时，使用用户的本地时区
- 如果无法判断是任务还是事件，默认创建任务

{可选上下文注入：今日事项摘要 / 近期事项摘要 / 复盘数据}
```

### 意图识别规则

1. 先尝试用本地规则匹配（LocalAIIntentParser），常见模式不调用 AI API
2. 本地无法匹配时，发送给 AI 服务商解析
3. AI 返回结构化 JSON → 解析为对应意图 → 展示确认页
4. AI 返回纯文本（非结构化）→ 直接作为聊天回复展示

### 本地解析优先模式（LocalAIIntentParser）

以下模式应在本地解析，不调用 AI API：

| 输入模式 | 解析结果 |
|---------|---------|
| 「明天下午三点开会」 | create_event: title="开会", startDate=明天15:00 |
| 「提醒我周五交报告」 | create_task: title="交报告", dueDate=周五 |
| 「买菜」 | create_task: title="买菜", dueDate=今天 |
| 「下周一到周三出差」 | create_event: title="出差", startDate=下周一, endDate=下周三 |

复杂输入（多任务、需要拆解、含歧义）交给 AI 服务商处理。
