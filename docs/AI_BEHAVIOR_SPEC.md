# 1Day — AI 行为规范

> 版本：v3.1 · 最后更新：2026-09-20
> 目的：约束 AI 功能的行为边界，防止 AI Coding 写出"AI 直接保存数据"等违背产品原则的逻辑。
> 家族级原则见：PRODUCT_PRINCIPLES.md 第四节
> 「已实现」小节以代码为准（`1Day/Services/AI/AIService.swift`）；V1.2 / V1.3 条目仍是规划。

---

## 一、AI 可以做

### 生成草稿

- 根据用户自然语言输入，生成结构化的任务/事件/想法草稿
- 从用户输入中提取日期、时间、优先级等结构化字段
- 生成复盘摘要（基于用户主动请求 + 已完成/未完成统计数据）
- 建议笔记分类或整理方案

### 读取上下文（仅用户主动触发时）

**已实现**：只有这句话确实指向计划对象时，才注入任务标题。

- `AIContextPolicy.needsPlanContext(for:)` 判定：明确指向任务的创建指令，或包含
  「任务 / 待办 / 计划 / 安排 / 日程 / 提醒 / 截止 / 复盘 / 周报 / 清单 / 进度 / 事项」等词
- 「今天」「明天」这类裸时间词不算触发条件——「今天天气怎么样」不会带出任何任务标题
- 命中时注入的是 `AIDataContext`：所选日期当天未完成任务标题（最多 10 条）+
  之后 7 天内未完成任务标题（最多 10 条，按截止日期排序）
- 笔记标题和正文永远不在这个结构里，V1.0 也没有读取复盘统计数据的实现

### 交互

- 在聊天界面回答用户关于计划、日程的问题
- 提供快捷建议 Chips（预设常见操作）
- 处理语音输入转文字后的文本
- 处理用户主动附加的图片（最多 6 张，压缩后随本次请求发送）

## 二、AI 不可以做

### 绝对禁止

- ❌ **直接写入数据库**：所有 AI 输出必须先作为草稿展示，经用户确认后才保存
- ❌ **自动删除或修改用户已有数据**：AI 不能修改已保存的任务/笔记/事件
- ❌ **后台静默调用 AI 模型**：每次 AI 请求必须由用户主动触发（发送消息、点击按钮）
- ❌ **擅自读取全部数据**：AI 上下文只包含当前任务所需的最少数据
- ❌ **读取笔记全文内容**：除非用户主动请求（如"帮我整理这条笔记"），否则不发送笔记正文给 AI
- ❌ **读取证件信息**：证件数据永远不发送给 AI 服务商
- ❌ **提供医疗/法律/金融建议**

### 行为约束

- AI 输出必须标注「AI 生成」或「草稿」
- AI 确认页必须允许用户编辑每一个字段
- AI 确认页必须有「取消」按钮，取消后不写入任何数据
- AI 请求超时必须有明确的错误提示和重试入口
- AI 解析失败时，保留用户原始输入，不丢弃

**已实现的对应行为**：

- 确认页可编辑标题、备注、日期、优先级和提醒时间；提醒时间预填用户在设置里定的默认值，
  而不是写死 09:00
- 「停止」按钮取消网络任务本身，被取消的请求不写消息、不弹确认卡、不报失败
- 请求失败时保留原文与图片，给出错误 Banner 和「重试」；重试成功与首次成功走同一条
  「解析 → 草稿 → 确认」路径，文本、图片、重试三种来源都必须经过确认才会落库
- 纯聊天回复（没有结构化草稿）不会打开确认卡

## 三、AI 上下文规则

### 什么数据可以发送给 AI

| 数据 | 是否发送 | 条件 |
|------|---------|------|
| 用户当前输入的消息 | ✅ 总是 | — |
| 对话历史 | ✅ 总是 | 最近 8 条（V1.0 实现，含图片消息的 `[图片附件]` 占位文本） |
| 当日任务标题 | ✅ 按意图 | 仅 `needsPlanContext` 命中时，最多 10 条 |
| 未来 7 天任务标题 | ✅ 按意图 | 仅 `needsPlanContext` 命中时，最多 10 条 |
| 用户主动附加的图片 | ✅ 按动作 | 最多 6 张，逐张压到大小上限内；压不进就明确失败，不发超限原图 |
| 完成统计数据（复盘） | ❌ V1.0 不发 | 属 V1.3 规划 |
| 笔记标题 / 正文 | ❌ 永不 | 上下文结构里没有这两个字段 |
| 证件信息 | ❌ 永不 | — |
| API Key | ❌ 永不 | Key 只用于 HTTP 请求头，不进 prompt |

### 摘要注入格式

当 AI 需要用户数据作为上下文时，只发送摘要，不发送完整数据。

```
今天：交房租、下午开会、买菜
未来 7 天：明天 交报告、周三 团队周会、周五 提交方案
```

## 四、结构化意图 JSON Schema

### V1.0：create_task（已实现）

**AI 输出格式**：
```json
{
  "intent": "create_task",
  "data": {
    "title": "交房租",
    "notes": "转账到房东招商银行",
    "dueDate": "2026-07-01T00:00:00Z",
    "priority": "high",
    "reminderTime": null
  }
}
```

**字段规则**：
- `title`：必填，String
- `notes`：可选，String，默认 ""
- `dueDate`：可选，ISO 8601 格式，nil 表示不设日期
- `priority`：可选，枚举 "none" / "low" / "medium" / "high"，默认 "none"
- `reminderTime`：可选，ISO 8601 格式；有值即视为用户要自定义提醒，确认卡会带出这一项

**AI 无法确定的字段**：设为 null，确认页让用户手动填写。

**解码规则**（`AIIntentDecoder`，实际比 schema 更宽容在哪、更严格在哪）：

- 接受 ``` 围栏内的 JSON，也接受夹在自然语言里的裸对象——服务商经常在草稿前后加一句说明
- `intent` 必须是 `create_task`，`data.title` 必须存在且非空白，否则整段视为纯聊天回复
- 可选字段缺失或为 null 不报错；日期解析失败按 nil 处理，交给确认页
- 不猜测：字段类型不对（例如 `priority` 给成对象）不会「尽力转换」成草稿

## 五、Prompt 构建规则

### 系统 Prompt 结构

```
你是 1Day 的 AI 助手，帮助用户管理任务和日程。

你的能力：
- 根据用户描述创建任务或事件草稿
- 回答关于计划和日程安排的问题
- 帮助用户回顾和复盘

规则：
- 你只生成草稿，用户确认后才会保存
- 如果用户的描述不够清晰，主动询问缺少的信息
- 日期解析时，使用用户的本地时区
- 需要返回结构化任务时，按 create_task 的 JSON 契约输出

{仅当本次输入指向计划对象时注入：当日任务标题 / 未来 7 天任务标题}
```

### 意图识别顺序（已实现）

1. 未配置 AI 服务商：只用本地规则 `LocalAIIntentParser`；命中就出草稿，未命中给一条说明性回复，
   **不发任何网络请求**
2. 已配置：把输入连同最近 8 条历史和（按需的）任务标题发给所选服务商
3. 回复优先按 `create_task` 结构化 JSON 解析；解不出来再退回本地规则解析回复文本
4. 两条路径都只产出草稿；仍无草稿时，回复作为普通聊天消息展示

### 本地规则能识别什么（`LocalAIIntentParser`，V1.0）

| 输入模式 | 解析结果 |
|---------|---------|
| 「提醒我周五交报告」 | create_task: title="交报告", dueDate=下个周五 |
| 「明天提交周报，重要」 | create_task: title="提交周报", dueDate=明天, priority=high |
| 「今天下午三点开会」 | create_task: dueDate=今天，时刻留在标题文本里（**不解析时刻**） |

- 日期只认：今天 / 今日、明天 / 明日、后天、周X / 星期X
- 优先级只认：高优先级 / 重要 / 紧急 → high，中优先级 / 一般优先 → medium，低优先级 / 不急 → low
- 不解析具体时刻、时间段、重复规则，也不产出事件——这些属于 V1.2 规划
- 意图判定顺序：真疑问词或问号 → 排除；明确创建动词 → 通过（句尾「吧 / 呢 / 吗」是礼貌语气，
  不影响判定）；没有创建动词时语气词仍按疑问排除；最后才是「日期词 + 动作词」组合

### 图片输入（已实现）

- 一次最多 6 张，超出按提交顺序截断
- 每张沿尺寸阶梯 + 质量阶梯压到上限内；压不进就返回明确错误，不发超限原图
- 图片列表为空时不构造视觉请求
- 视觉请求保留完整对话历史，图片挂在当前这一轮上

## 六、请求生命周期

| 阶段 | 行为 |
|------|------|
| 发送中 | 进度可见，「停止」可用 |
| 用户停止 | 取消网络任务本身；晚到的响应一律丢弃，不产生确认卡或消息 |
| 请求失败 | 保留原文与图片，错误 Banner + warning 触觉，提供「重试」 |
| 重试成功 | 与首次成功走同一条解析与确认路径 |
| 有草稿 | 打开确认卡；未确认不写库 |
| 无草稿 | 作为普通回复展示 |
| 确认后创建 | 写入任务 + 记录一条带 `toolName = create_task` 的助手消息，并给出撤销入口 |
