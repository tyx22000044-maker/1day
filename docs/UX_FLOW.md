# 1Day — 用户流程

> 版本：v3.1 · 最后更新：2026-09-20
> 目的：描述用户一步一步怎么走，让页面、按钮、状态变化更清楚。
> Flow 1–4、7–11 以当前实现为准；标了 [V1.1] / [V1.2] / [V1.3] 的条目仍是规划。

---

## Flow 1：快速创建任务（今日视图输入栏）

**入口**：Tab 1 今日视图，顶部快速输入栏

```
1. 用户点击输入栏 → 键盘弹出
2. 输入文字（如"买菜"）
3a. 按回车 →
    3a.1 创建 PlanItem: title="买菜", dueDate=今天, priority=.none, status=.pending
    3a.2 任务出现在今日列表中（从底部滑入动画 0.3s）
    3a.3 触觉反馈（success）
    3a.4 输入栏清空，键盘保持（方便连续输入）
    3a.5 如果是第一次设置日期 → 触发通知权限请求
3b. 长按发送按钮（`Menu` + `primaryAction`：单击=今天，长按弹出菜单）→
    3b.1 三个快捷选项：今天 / 明天 / 稍后安排
    3b.2 选择"稍后安排" → 创建 PlanItem: dueDate=nil（出现在 Tab 2"未安排"分组）
    3b.3 选择今天或明天 → 创建 PlanItem: dueDate=对应日期
    3b.4 单击发送 = 按 3a 的当前所选日期创建
    （未实现：菜单里的「本周」和「选择日期」两项）
4. 输入为空时按回车 → 无操作
```

> 交互口径（2026-09-20 与实现同步）：任务/笔记列表是 `ScrollView` + `SystemPanel`
> 自绘分组，不是 `List`，没有行级 `swipeActions`。行级操作统一走**长按菜单
> （context menu）**，详情页提供同等入口；输入栏发送按钮的长按菜单是另一处
> 长按交互，两者不要混淆。

## Flow 2：完整创建任务（+ 按钮）

**入口**：Tab 1 或 Tab 2 右上角 + 按钮

```
1. 点击 + 按钮 → 弹出 Sheet（从底部滑入）
2. Sheet 内容（表单）：
   - 标题（TextField，必填，占位文字"任务标题"）
   - 备注（TextEditor，可选，占位文字"添加备注…"）
   - 「设置日期」开关 → 打开后出现日期 DatePicker（Tab 1 入口默认带上当前所选日期）
   - 「设置提醒」开关 → 打开后出现时间 DatePicker，
     预填用户在设置里定的默认提醒点，并落在所选日期那一天（不是写死 09:00）
   - 优先级（Picker：无 / 低 / 中 / 高）
   - [V1.1] 收藏集（Picker，可选）
   - [V1.1] 标签（多选，可选）
3. 底部「保存」按钮：标题为空白时直接置灰不可点（不是点了之后标红提示）
4. 点击「保存」→
   4.1 创建 PlanItem
   4.2 有 dueDate → 按「自定义提醒时间或默认提醒点」调度本地通知
   4.3 触觉反馈（success）
   4.4 关闭 Sheet，任务出现在对应分组
5. 点击「取消」→ 关闭 Sheet，不保存任何数据
```

## Flow 3：AI 创建任务（聊天 → 确认卡）

**入口**：Tab 3 AI 聊天界面

```
1. 用户在输入框输入自然语言（如"明天下午开会讨论 Q3 计划"），可附加图片（最多 6 张）
2. 点击发送 →
   2.1 用户消息立即写入本机历史并显示在右侧气泡
   2.2 进度可见（等待秒数）+「停止」按钮
3. 解析路径：
   3a. 未配置服务商 → 只用本地规则，不发网络请求；命中出草稿，未命中回一句说明
   3b. 已配置 → 请求服务商（文本 30s、图片 45s 超时）
   3c. 回复先按 create_task 结构化 JSON 解析，解不出再用本地规则解析回复文本
   3d. 两条都不认 → 回复作为普通聊天气泡展示，不弹确认卡
4. 有草稿 → 直接弹出确认 Sheet：
   - 标题 / 备注 / 日期 / 优先级 / 提醒开关 + 提醒时间
   - 提醒时间预填设置里的默认点；AI 已给出提醒时间时带出 AI 的值
   - 每个字段都可编辑
5a. 点击「确认」→
    5a.1 创建 PlanItem 并调度通知
    5a.2 AI 侧气泡更新为「已创建：<标题>」（带 toolName = create_task 的历史记录）
    5a.3 底部出现 3 秒撤销条，触觉 success
5b. 点击「取消」→ 关闭 Sheet，草稿丢弃，不写任何数据
6. 撤销条点击 →
   6.1 删除刚创建的 PlanItem 并取消对应通知
   6.2 触觉 warning
```

**错误与中断**：
```
- 请求进行中点「停止」→ 取消网络任务本身；晚到的响应丢弃，不写消息、不弹确认卡
- 超时 / 网络失败 / 服务商报错 → 顶部错误 Banner 给出具体原因 + 触觉 warning，
  原始输入与图片保留，可点「重试」；重试成功走与首次成功完全相同的确认路径
- 当前服务商没有 Key → 提示去「设置 → AI 配置」，并保留入口
- 图片压不进大小上限 → 明确报"图片超限"，不发超限原图
- 未配置服务商且本地规则没命中 → 回一句能力说明，不发请求
```

## Flow 4：创建独立笔记

**入口**：Tab 4 笔记列表，右上角 + 按钮

```
1. 点击 + 按钮 → 进入笔记编辑页（Push 导航）
2. 编辑页内容：
   - 标题（TextField，可选，占位文字"笔记标题"）
   - 正文（TextEditor，占位文字"开始写…"）
   - 导航栏保存状态：只有 save() 真的成功才亮「已保存」，失败时给出错误而不是照常显示已保存
   - [V1.1] 标签选择
3. 用户编写内容
4. 点击返回（导航栏 Back 按钮）→
   4.1 打开时就是空的草稿、离开时仍然是空的 → 丢弃，不留一条「空笔记」
   4.2 有内容 → 保存 Note；保存失败会提示，不假装已保存
   4.3 返回笔记列表，新笔记出现在列表顶部
5. 编辑已有笔记 → 点击列表中的笔记 → 进入编辑页 → 修改 → 返回保存
   把一条曾有内容的笔记清空后返回：笔记保留（内容变成空），不在用户没要求的情况下删除记录
6. 删除笔记 → 长按列表中的笔记 → 「删除」→ 二次确认（说明 5 秒后可撤销、超时只能从备份恢复）
   → 删除并保存
   6.1 删除后列表底部出现 5 秒撤销条，点「撤销」按原 id 和内容恢复
   6.2 撤销窗口内不做任何事，超时后撤销条自动消失
```

## Flow 5：从事件添加笔记（V1.2）

**入口**：事件详情页底部「笔记」区域

```
1. 用户从 Tab 1 或 Tab 2 点击一个事件 → 进入事件详情页
2. 详情页底部显示「笔记」区域：
   - 已有笔记列表（标题 + 内容预览）
   - 「添加笔记」按钮
3. 点击「添加笔记」→ 进入笔记编辑页
   3.1 编辑页顶部显示关联信息：「关联：Q3 规划会议 · 10:00-12:00」
   3.2 自动设置 Note.linkedItem = 当前事件
4. 编写笔记 → 返回自动保存
5. 保存后：
   5.1 笔记出现在事件详情页的笔记列表中
   5.2 同一条笔记也出现在 Tab 4 笔记列表中（带关联事件标签）
6. 从 Tab 4 点击有关联的笔记 → 进入编辑页 → 顶部显示关联事件 → 可点击跳转到事件详情
```

## Flow 6：证件照片保存和取用（V1.3）

**入口**：Tab 5 设置 → 证件管理

```
1. 点击「证件管理」→ Face ID / Touch ID 验证
   1a. 验证成功 → 进入证件列表页
   1b. 验证失败 → 提示「认证失败，请重试」，不进入
2. 证件列表页：
   - 网格布局，每张证件显示：类型图标 + 名称 + 到期状态
   - 到期状态：绿色「有效」/ 橙色「即将到期」（30天内）/ 红色「已过期」
   - 右上角 + 按钮添加新证件

添加证件：
3. 点击 + → 进入添加证件 Sheet
4. 填写：
   - 证件名称（如"我的护照"）
   - 证件类型（Picker：身份证/护照/驾照/港澳通行证/社保卡/其他）
   - 正面照片（点击拍照或从相册选择）
   - 反面照片（可选）
   - 到期日期（可选，DatePicker）
   - 备注（可选）
5. 点击「保存」→
   5.1 照片保存到 Documents/Credentials/ 目录
   5.2 Document 模型保存到 SwiftData
   5.3 如果设置了到期日期 → 调度到期前 30 天的本地通知
   5.4 返回证件列表

使用证件（典型场景：上传身份证照片）：
6. 点击证件卡片 → 进入证件详情页
7. 查看正反面照片（支持缩放手势）
8a. 长按照片 → 弹出菜单：「保存到相册」/「分享」
8b. 点击底部「保存到相册」按钮 → 保存所有照片到 Camera Roll → toast 提示「已保存」
8c. 点击底部「分享」按钮 → 系统分享 Sheet → 可发送到微信/邮件等
9. 切换到需要上传照片的 App → 从相册选取
```

## Flow 7：任务完成 + 通知取消

```
1a. 今日视图（Tab 1）长按任务 → 「标记完成」→
1b. 计划列表（Tab 2）长按任务 → 「标记完成」→
1c. 任务详情页 → 「标记完成」按钮 →
1d. 通知横幅点击「标记完成」→

2. PlanItem.status = .completed
3. PlanItem.completedAt = now
4. 划过横线动画（0.3s）
5. 触觉反馈（success）
6. 任务移至「已完成」区域（灰显）
7. 如果有对应的 pending notification → UNUserNotificationCenter.removePendingNotificationRequests(withIdentifiers:)
8. Tab 1 底部进度卡片更新（今日完成数 +1）
```

**撤销完成**：
```
1. 在「已完成」区域点击任务 → 进入详情
2. 点击「标记未完成」→
   2.1 PlanItem.status = .pending
   2.2 PlanItem.completedAt = nil
   2.3 任务回到待办列表
   2.4 如果有 dueDate 且未过期 → 重新调度通知
```

## Flow 8：Onboarding 全流程

共 6 步，每步底部一个主按钮；进度条可回退。

```
1. Welcome
   - 标题：「欢迎使用 1Day」+ 副标题 + 三个价值点
   - 「开始」→ Profile

2. Profile（设置你的资料）
   - UserAvatarView（SF Symbol 头像 or 相册照片，照片压到 512 KB 内）
   - 昵称 TextField（可为空）
   - 「继续」→ 偏好

3. 偏好（选择使用偏好）
   - 语言 / 外观两个分段 Picker（系统 / 简体中文 / English；系统 / 浅色 / 深色）
   - 「继续」→ AI 配置

4. AI 配置（可跳过）
   - 服务商选择 + 模型 + API Key 输入 + 「测试连接」
   - 「跳过」和「继续」都会把已经填进来的 Key 一起存进 Keychain（填了不等于丢）
   - 未填 Key → 跳过就是真的跳过，AI 功能不可用但其余功能完整
   - 「继续」→ 提醒时间

5. 提醒时间
   - 「每天几点提醒你待办事项？」+ 时间 Picker + 预设 08:00 / 09:00 / 10:00 / 18:00
   - 「开启通知权限」按钮：授权成功 → success 触觉；被拒绝 → warning 触觉、
     明说「任务到期不会有任何提醒」，并给出「打开系统设置」入口
   - 「继续」→ 完成

6. Ready
   - 摘要卡片：昵称、提醒时间、AI 状态
   - 「开始使用」→ 写入 hasCompletedOnboarding 并显式 save()，触觉 success
   - save() 失败 → 错误 Banner 说明没保存成功和原因，不会静默回到 onboarding
```

> 每一步只改内存里的 `UserSettings`，最后一次显式 `save()` 落盘；
> 中途杀进程会重新进入 onboarding，而不是留下半套设置。

## Flow 9：数据备份与恢复

**入口**：Tab 5 设置 → 数据管理

### 备份

```
1. 点击「导出备份」
2. 生成 JSON 文件，包含：
   - 所有 PlanItem（含完成时间、自定义提醒时间、原始创建/更新时间）
   - 所有 Note
   - UserSettings（含头像照片 avatarImageData）
   - schemaVersion = 2
   - [V1.1] Collection、Tag
   - [V1.3] Idea、ReviewEntry、Document 元数据（不含照片）
   - 不含：AI API Key（只在 Keychain）、AI 聊天历史、证件照片
3. 提示「备份文件已生成」→「分享备份文件」走系统分享 Sheet → 用户选择保存位置
   （文件 / AirDrop / 云盘等）；App 不长期保存副本，文件写在临时目录
4. 触觉反馈（success）；导出失败给出具体原因
```

### 恢复

```
1. 点击「导入备份」→ 系统文件选择器
2. 选中文件 → 确认弹窗「导入备份将替换当前数据」：
   「会替换任务、笔记和设置，并重建任务提醒。建议先导出当前备份。」
   按钮：「取消」/「导入」（destructive）
3. 点击「导入」→ 先整体解码并校验，全部通过才动现有数据：
   3a. 格式版本高于当前 App → 明确拒绝并说明版本差，现有数据一字未动
   3b. 枚举读不懂、标题为空、提醒小时/分钟越界、文件内 id 重复 → 指出具体字段和值，
       现有数据一字未动
   3c. 校验通过 → 关闭 autosave，删除旧数据、写入新数据（沿用原 id 和时间戳），一次 save()
   3d. save() 失败 → 整体回滚到导入前状态；不会出现「删了一半又没导进来」
   3e. 保存成功后才取消旧通知、按恢复出的任务重建提醒
4. 成功 → 提示「备份已恢复」+ 触觉 success
5. 失败 → 提示「导入失败：<原因>」，并明确说明现有数据没有被改动
```

### 清空数据

```
1. 点击「清空任务和笔记」
2. 第一次确认：「会删除所有任务、笔记和待办提醒，但保留个人资料和 AI 配置。」
   按钮：「取消」/「继续」
3. 第二次确认：「此操作不可撤销。建议先导出备份。」
   按钮：「取消」/「清空所有数据」
4. 点击「清空所有数据」→
   4.1 取消所有任务提醒、删除全部 PlanItem 和 Note
   4.2 个人资料、设置和 AI 配置保留（要单独清 AI 聊天历史去「AI 配置」页）
   4.3 触觉反馈（success，失败 warning）
   4.4 [V1.3] 删除证件照片文件
```

## Flow 10：存储不可用时怎么办

**触发**：SwiftData 打不开本地数据库（沙盒不可写、磁盘满、store 损坏）

```
1. App 仍会启动，但落到内存容器：本次修改不会保存
2. 每个 Tab 顶部常驻一条不可关闭的风险提示：
   「存储不可用 · 本次修改不会保存」+ 原因 + 建议
3. 提示里直接给出「导出备份 / 分享」出口，让用户在退出前把当前内容带走
4. 用户重启 App 再次尝试打开数据库；恢复正常后提示自动消失
```

> 这里不做静默兜底：以前容器创建失败会悄悄换成内存容器，用户以为数据在，
> 退出后任务和笔记一起消失，而且没有任何一条信息说明发生过什么。

## Flow 11：提醒权限与调度反馈

**入口**：Tab 5 设置 → 提醒时间

```
1. 「通知权限」面板显示系统里的真实状态（已开启 / 可静默显示 / 已拒绝 / 尚未授权），
   以 UNUserNotificationCenter 为准，而不是 App 内记住的开关
2. 状态需要用户动手时给出「打开系统设置」入口
3. 创建或改期一个带日期的任务 → 调度提醒：
   3a. 权限已被系统拒绝 → 顶部 Banner「提醒不会送达」+ 去系统设置的说明
   3b. 系统没接受这条请求 → Banner「提醒设置失败」+ 具体原因，并说明任务本身已保存
   3c. 尚未授权 → 先静默记日志，由请求授权流程处理，不弹一条用户看不懂的错误
4. 修改默认提醒时间 → 跟随默认的未完成任务立即重排；新默认点已过去的撤销通知；
   带自定义提醒时间的任务不受影响
5. 同一任务连续快速改期 → 只有最后一次操作落地，不会留下指向旧日期的通知
```

## Flow 12：删除任务

**入口**：Tab 1 / Tab 2 长按任务 → 「删除」，或任务详情页的删除行

```
1. 触发删除 → 先弹二次确认：
   「删除后 5 秒内可以在列表底部撤销，超时后就只能从备份恢复了。」
   按钮：「取消」/「删除」
2. 确认 → 先做值快照（标题、备注、日期、优先级、提醒时间、完成时间、创建/更新时间），
   再删除并保存，同时取消这条任务的待办提醒
3. 底部出现撤销条（5 秒窗口）→
   3.1 点「撤销」→ 按快照原样建回记录，id 不变
   3.2 超时 → 撤销条消失，数据仍在备份里才可能找回
4. 删除失败（存储不可用等）→ 给出错误提示，不留下「已删除但没保存」的中间状态
```

> 快照必须在删除之前取：对象一旦从上下文移除就失效，只有值拷贝能把任务原样建回来。
